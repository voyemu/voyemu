# passion-11-russian-20260403-2.1.4.80

Русская прошивка Voyah Passion 2.1.4.80 от 3 апреля 2026 года на Android 11. Мультимедиа поддерживается, приборка экспериментальная.

Профиль объявляет две [цели сборки](../how/profiles-machines.ru.md#цели-сборки) с общими оригиналами прошивки H53 и рецептами.

## Гости

| Цель | ABI Android | Эмулятор | Приборка |
| --- | --- | --- | --- |
| `arm` | `arm64-v8a` | 2048 МиБ, 4 ядра | QNX, экспериментальная |
| `x86` | `x86_64` | 4096 МиБ, 4 ядра | Нет |

Обе цели используют API 30 и руль `passion-2024`.

## Цель x86

Цель `x86` запускает мультимедиа в госте x86_64: с аппаратным ускорением на хосте с процессором x86_64, на другом хосте — в программной трансляции. Её [ядро разработки](../how/components.ru.md#ядра-разработки) x86_64 ещё не опубликовано, поэтому подготовка этой цели останавливается с `PROFILE_TARGET`. Подготовка проверяет оба штатных рабочих стола и их службы Android Binder. В этой цели доступны адаптер MCU Voyemu для уровня заряда батареи и раздельное управление питанием дисплеев мультимедиа.

Звук выводится через локальный сокет PulseAudio, захват с микрофона выключен. По умолчанию используется `$XDG_RUNTIME_DIR/pulse/native`. Для другого локального сокета задайте `PULSE_SERVER=unix:/путь/к/сокету`. Если доступного сокета нет, Android запускается без звука. При холодном старте прошивка выставляет минимальную громкость. Чтобы услышать звук, поднимите её штатным регулятором.

Подготовка использует образ API 30 `default` x86_64 r11. Обычная перезагрузка r11 проходит успешно. После штатной команды Android `remount` проверка Android Verified Boot отклоняет изменённые загрузочные метаданные при перезагрузке, ещё до копирования первого оригинала прошивки. Для этой цели системные файлы собираются до создания деревьев хешей и подписи образов локальным ключом разработчика. Закреплённые файлы ARM Native Bridge из Google APIs r16 позволяют штатной службе `MonzaCarService` загрузить ARM64-библиотеку JNI и зарегистрировать сервис, от которого зависят оба рабочих стола. См. [подготовку](../how/preparation.ru.md#build) и [профили как исходники, машины как результат](../why/profiles-machines.ru.md).

Перед подписью системного образа профиль устанавливает `ro.build.display.id` в значение `V2.1.4.80-20260403174306` из прошивки H53. Android отдаёт этот идентификатор через `Build.DISPLAY`.

### Подготовка и запуск

Собрать [лаунчер из исходников](../dev/build.ru.md) закреплённым набором инструментов Linux с JDK 25. Выполнить команды из корня рабочей копии в графическом сеансе с аппаратным ускорением и доступом к `/dev/kvm` и устройству рендеринга GPU. Эмулятору из SDK нужны библиотеки Qt и X11, в том числе `libxkbfile.so.1`, `libSM.so.6` и `libICE.so.6`. Сборка образа использует e2fsprogs, binutils, `jq`, `unzip` и команду `openssl`. Подготовка получает закреплённые инструменты через `curl`, распаковывает их с помощью `dpkg-deb` и запускает `avbtool` на Python 3.

Команды получают локальный путь к `OIB_8155_H53Y3632802AW.zip`. `deps` и `build` используют JDK разработчика для [помощника Java](../dev/ci.ru.md#рабочий-процесс-java-helper), пока не закреплён архив с поддержкой целей сборки. На хосте x86_64 цель `x86` выбирается по умолчанию, а машина создаётся в `machines/PROFILE`.

Для сборки компонента HAB из исходников нужен Android NDK r29 (`29.0.14206865`). Отдельно от `deps` скачайте полный архив NDK для Linux по URL и SHA-256 из `sdk.archives.linux.ndk` в [`src/app/toolchain.json`](../../src/app/toolchain.json). Сверьте SHA-256, распакуйте архив вне каталога SDK, который устанавливает Voyemu, и задайте в `NDK_HOME` абсолютный канонический путь к каталогу с `source.properties`. Voyemu сверяет содержимое внешнего NDK с пином.

```sh
profile=passion-11-russian-20260403-2.1.4.80
firmware=/path/to/OIB_8155_H53Y3632802AW.zip
jdk="$PWD/.local/toolchains/jdk-25.0.5+8"
machine=machines/${profile}
export NDK_HOME=/path/to/android-ndk-r29

./voyemu deps "$profile" --jdk "$jdk"
./voyemu fetch "$profile" --source="$firmware"
./voyemu build "$profile" --jdk "$jdk"
./voyemu check "$machine"
./voyemu start "$machine"
./voyemu status "$machine"
```

Ход загрузки Android виден при повторном вызове `status`. После работы остановить сеанс. Каталог машины и записываемые диски сохраняются для следующего запуска.

```sh
./voyemu stop "$machine"
```

## Оригиналы

`fetch` импортирует закреплённый архив прошивки `OIB_8155_H53Y3632802AW.zip` по локальному пути, читает пакет OTA внутри него и извлекает общие оригиналы для обеих целей. Внутренний TGZ также можно передать напрямую под именем из манифеста обновления. Команда сверяет размер и SHA-256 файла.

Цель `arm` готовится по [общей инструкции](../how/preparation.ru.md). На Apple Silicon она выбирается по умолчанию, а машина создаётся в `machines/passion-11-russian-20260403-2.1.4.80`. На хосте с процессором x86_64 её выбирает `--target=arm`; гость тогда работает в программной трансляции в `machines/passion-11-russian-20260403-2.1.4.80-arm`. `--cluster=off` готовит только мультимедиа.

```sh
./voyemu build passion-11-russian-20260403-2.1.4.80 --cluster=off --jdk "$jdk"
```

## Замечания

Для цели `arm` команда `build --force` с подготовкой только мультимедиа обновляет систему Android существующей остановленной машины и сохраняет записываемые диски. Для подписанной сборки `x86` нужен новый каталог машины. См. [подготовку](../how/preparation.ru.md).

Список приложений показывает девять плиток автомобиля в его порядке: «Машина», «Bluetooth Телефон», «Сценарии», «Вид 360 градусов», «Запись вождения», «Камера», «Фото», «Музыка» и «Видео». Каждая плитка открывает штатное приложение прошивки, в том числе `com.voyah.scenemode` для «Сценариев», `com.mega.dvr` для «Записи вождения» и `com.voyah.gallery` для «Фото». «Фото» и «Сценарии» работают с системными правами, как в автомобиле, поэтому «Фото» читает снимки и видео внутренней памяти и USB-накопителей. «Запись вождения» показывает виртуальную камеру, см. [запись вождения Passion](../how/camera.ru.md#запись-вождения-passion).

При включении окно, как автомобиль, одновременно воспроизводит три штатных стартовых ролика из `ifs_video.img` внутри `ifs2_la.img`; отдельный импорт не нужен. На основном экране идёт `proc/boot/startup_video_screen_2.mp4`, на втором — `proc/boot/startup_video_screen_3.mp4`, оба не дольше 5 с. Если окно показывает приборку, в её области не дольше 3 с идёт `proc/boot/startup_video_screen_0.mp4`. После своего ролика основной экран показывает штатную загрузочную анимацию до готовности Android. Профиль импортирует только загрузочную анимацию основного экрана, поэтому второй экран после своего ролика остаётся чёрным, см. [окно](../how/window.ru.md#экран-запуска).

У автомобиля есть четвёртый экран 1280×720 — второй экран QNX с ролью экрана `hud`. Его показывает [окно экранов](../how/window.ru.md#экраны): штатный стартовый ролик `proc/boot/startup_video_screen_1.mp4` до 3 с, затем чёрный экран, потому что вывод QNX на этот экран пока не эмулируется.
