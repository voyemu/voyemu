# Linux x64 как хост

## Решение

Linux x64 — такой же хост, как macOS на Apple Silicon и Windows x64. Лаунчер собирается под glibc 2.34 и берёт TLS и криптографию из системы: для загрузок он загружает libcurl (`libcurl.so.4`), для подписи APK — libcrypto из OpenSSL 3 (`libcrypto.so.3`).

## Контекст

Многие разработчики и исполнители CI работают на Linux. RHEL 9, Ubuntu 22.04 и Debian 12 поставляют glibc 2.34 или новее вместе с libcurl и OpenSSL 3. Для мультимедиа Passion закреплённому Android Emulator в Linux x64 нужен системный образ Android x86_64. [Цель `x86` профиля Passion](../profiles/passion-11-russian-20260403-2.1.4.80.ru.md#цель-x86) использует этот ABI с аппаратным ускорением и GPU хоста.

## Альтернативы

**Linux только для сборки и тестов.** Общий код компилировался бы и проходил тесты на Linux, но пользователи Linux не могли бы подготавливать и запускать машины.

**Закреплённая библиотека TLS внутри лаунчера.** Voyemu пришлось бы поставлять и обновлять свой код TLS, и он не следовал бы системному хранилищу сертификатов.

## Аргумент

[Одна реализация](single-implementation.ru.md) держит код хоста в тонких бэкендах `os/`, поэтому Linux добавляет бэкенды, а не ветки в общем коде. Системные библиотеки сохраняют ABI под своими именами файлов и получают исправления безопасности от дистрибутива: загрузка при запуске оставляет лаунчер небольшим, а его TLS — свежим. Тот же исполнитель CI на Linux прогоняет clang-tidy по общему коду и кросс-компилирует исполняемый файл Windows [набором инструментов Zig](zig-toolchain.ru.md).

## Последствия

У Linux свои бэкенды `os/`; системные библиотеки загружают `curl_linux` и `rsa_linux`. Движок QNX выполняет приборку однопоточным TCG с часами движка Windows и держит RAM гостя в общем файле, как на macOS; это QEMU по рецепту `linux_x64` из `src/app/qnx-host.json`. Графический обработчик запускает ANGLE из закреплённого Emulator на бэкенде Vulkan, который рисует через драйвер Vulkan системы с дисплейным сервером и без него. Окно открывается на X11 или Wayland через SDL3, который загружает библиотеки X11, Wayland, xkbcommon и libdecor из системы. Без системной библиотеки `deps` или `build` останавливается с `DOWNLOAD_LIBRARY` или `APK_CRYPTO_LIBRARY` и называет её; см. [deps](../how/preparation.ru.md#deps). Страница [Сборка](../dev/build.ru.md) приводит файлы набора инструментов и базу glibc.
