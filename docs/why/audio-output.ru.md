# Вывод звука без хоста

## Решение

Если у мультимедиа есть звук, а хост не может его воспроизвести, Voyemu запускает эмулятор Android с аудиодрайвером QEMU `none`, а не с `-no-audio`. Гость сохраняет звуковое устройство, пропадает только вывод на хост. `start` выводит причину, а `session.status` сообщает её, см. [звук](../how/launch.ru.md#звук). `-no-audio` остаётся для запуска с выключенным звуком.

## Контекст

Эмулятор выводит звук через драйвер QEMU хоста: Core Audio, DirectSound или PulseAudio. Такого вывода у хоста может не быть: на Linux бывает, что сокета PulseAudio нет или `PULSE_SERVER` называет сервер, до которого QEMU не дотягивается. `-no-audio` выключает звук всей конфигурации эмулятора, и тогда звуковое устройство гостя зависело бы от состояния хоста при каждом запуске. [Снимок RAM](../GLOSSARY.ru.md) Android привязан к настройке запуска, а не к хосту. Проверка громкости при старте и приёмка PCM читают аудиослужбу гостя.

## Альтернативы

**`-no-audio`, когда хост не воспроизводит звук.** Тогда гость загружается со звуковым устройством или без него в зависимости от хоста, снимок без устройства может встретить запуск с устройством, а о пропавшем звуке сообщает только запись лога.

**Остановить `start` с ошибкой.** Прошивка работает и без звука, поэтому хост без звукового сервера, например хост автоматизации, потерял бы всю машину из-за одного вывода.

## Аргумент

Драйвер `none` меняет только направление звука, поэтому гость, его снимок RAM и проверки звука видят одно устройство на любом хосте. Отсутствие вывода показывают одна строка `start` и одно поле `session.status`, а сам запуск проходит.

## Последствия

Пока у хоста нет сервера, аудиослужба гостя выводит звук в никуда, а следующий запуск с сервером воспроизводит его без других изменений. `deliveries.android.audio` сообщает `playing`, `unavailable`, `disabled` или `diagnostic`. На Linux в исполняемом файле эмулятора без окна нет PulseAudio, поэтому для воспроизведения запускается эмулятор с окном, и это окно скрывается.
