# Запуск и сеансы

Сеанс — один запуск гостей машины под управлением процесса-супервизора. Команды жизненного цикла принимают путь машины, запускают или останавливают её сеанс и выводят короткий текстовый результат. У машины не больше одного сеанса, а команда отклоняет сеанс другого каталога машины, даже с тем же профилем.

## Команды жизненного цикла

| Команда | Действие | Вывод при успехе |
| --- | --- | --- |
| `start MACHINE_PATH` | Запускает гостей и открывает [окно](window.ru.md) | Что сеанс запущен или машина уже работает, и команду `stop`; с `--verbose` — сеанс и его подсистемы |
| `restart MACHINE_PATH` | Проверяет выбор, останавливает сеанс и запускает его снова | Сеанс и его подсистемы |
| `status MACHINE_PATH` | Показывает активный сеанс | Машина, состояние сеанса и состояние каждого гостя |
| `stop MACHINE_PATH` | Останавливает сеанс и процессы гостей | `Session stopped:` и машина |
| `check MACHINE_PATH` | Проверяет сохранённые файлы и настройку запуска; ничего не устанавливает и не запускает | Профиль, установка и готовность каждой подсистемы к запуску |
| `patch MACHINE_PATH --values JSON` | Применяет значения к [модели автомобиля](vehicle.ru.md) | `Vehicle state updated:` и машина |

```sh
./voyemu start machines/free-09-chinese-20260106-6.0.3
./voyemu status machines/free-09-chinese-20260106-6.0.3
./voyemu patch machines/free-09-chinese-20260106-6.0.3 --values '{"speed":80}'
./voyemu stop machines/free-09-chinese-20260106-6.0.3
```

Команды жизненного цикла принимают путь каталога машины с `runtime.json`, относительный или абсолютный, в том числе вне корня установки; команды подготовки принимают имя профиля из `profiles/`, см. [подготовку](preparation.ru.md). `voyemu list` выводит идентификаторы профилей, включая незавершённые, `voyemu help` — полный синтаксис с параметрами подготовки, а `voyemu --version` — версию.

`status` выводит строку с состоянием сеанса, `running` или `stopped`, и состоянием мультимедиа и приборки: `ready`, когда гость подтвердил доставку, `off` для выключенного или остановленного гостя, `not started` до запуска гостя или текущее состояние запуска. Пока работает приборка, `status` выводит ещё путь к файлу обнаружения кадров QNX.

## Подсистемы

`--multimedia=on|off` и `--cluster=on|off` выбирают гостей для `start` и `restart`. Мультимедиа включена по умолчанию, приборка — если она есть в машине. Хотя бы одна подсистема остаётся включённой, а выключенная не запускает процесс гостя. Сменить выбор можно после остановки сеанса или через `restart` с новыми флагами.

## Несколько машин

Разные машины работают одновременно, каждая в своём сеансе. Каждый запуск занимает порты консоли и ADB своего эмулятора Android до того, как эмулятор их откроет, поэтому одновременные запуски получают разные порты. Порты, которые уже слушает другая программа, запуск пропускает.

`stop` также завершает эмулятор Android, если запуск прервался на полпути или супервизор сеанса завершился. Сигнал получает только эмулятор, который запустил этот сеанс: `stop` узнаёт его по времени старта процесса и токену сеанса. Если это доказать нельзя, команда завершается кодом с окончанием `_UNKNOWN` и оставляет сеанс работающим, см. [ошибки](errors.ru.md).

## Параметры запуска

| Параметр | Действие |
| --- | --- |
| `--network=yes\|no` | Исходящий NAT для гостя; по умолчанию выключен |
| `--background` | Держит окно и звук в фоне |
| `--resume` | Восстанавливает сохранённый сценарий автомобиля вместо значений по умолчанию |
| `--seconds 1..3600` | Ограничивает время работы QNX |
| `--provider FILE` | Регистрирует манифест провайдера, не больше четырёх; путь следует [правилу путей](preparation.ru.md) |
| `--verbose` | Выводит подробности сеанса после успешного `start` и записи лога в `stderr`, см. [логи](logs.ru.md) |

## Звук

Android выводит звук через аудиовыход хоста: Core Audio на macOS, DirectSound на Windows и PulseAudio на Linux. Захват с микрофона выключен.

На Linux Voyemu подключается к PulseAudio или к PipeWire через его сервер PulseAudio по локальному сокету из `PULSE_SERVER=unix:/путь/к/сокету`, а без этой переменной — по `$XDG_RUNTIME_DIR/pulse/native`.

Если хост не может воспроизводить звук, потому что сокет никто не слушает или `PULSE_SERVER` не называет локальный сокет, например задаёт адрес `tcp:`, Android всё равно запускается со звуковым устройством, а звук никуда не выводится. Тогда `start` выводит строку с причиной, а `deliveries.android.audio` операции `session.status` сообщает `state` `unavailable` и `reason` `no_server` или `unsupported_server`. Когда хост воспроизводит звук, `state` равен `playing`, а `driver` называет драйвер хоста. Почему гость сохраняет звуковое устройство, объясняет запись [вывод звука без хоста](../why/audio-output.ru.md).

## Язык вывода

Команды выводят текст; JSON пишет только `test`, см. [Voyemu API](api.ru.md). Справка, вывод и ошибки команд — на английском, русском или китайском. Язык выбирает `--lang=en|ru|zh` в любом месте командной строки; без него решает первая непустая переменная из `LC_ALL`, `LC_MESSAGES` и `LANG`, затем язык интерфейса хоста. При локали `C` или `POSIX`, неизвестном языке и без настройки вывод идёт на английском. Коды ошибок и JSON команды `test` во всех языках одинаковы. У [окна](window.ru.md) свой язык интерфейса.

## Снимок RAM Android

Когда сеанс останавливается и на диске хватает места, супервизор сохраняет RAM Android как снимок в `.local/machines/<name>/`. Следующий запуск восстанавливает его, если диски машины не менялись, а иначе запускает Android холодным стартом. `--resume` касается только сценария автомобиля и не обещает восстановления RAM.

## Ошибки

Неудачная команда выводит в `stderr` строку `Voyemu:` с `CODE: message` и завершается с кодом `4`; см. [ошибки](errors.ru.md). `start`, `restart`, `stop` и `patch` выводят ещё путь к своему [логу команды](logs.ru.md#лог-команды). Логи сеанса остаются в его каталоге, см. [логи](logs.ru.md).

## Кадры QNX по gRPC

Пока работает приборка, супервизор отдаёт её кадры по gRPC без шифрования на `127.0.0.1` и записывает закрытый файл обнаружения `qnx-frame-grpc.json` с `host`, `port` и `token` текущего поколения приборки. `status` выводит путь к файлу, а JSON операции `session.status` передаёт его в `deliveries.qnx.frame_grpc.discovery`. Клиент передаёт `authorization: Bearer <token>` в каждом вызове. После перезапуска приборки в файле новые порт и токен, поэтому клиент читает файл заново.

Сервис — `android.emulation.control.EmulatorController` из `emulator/lib/emulator_controller.proto` в SDK: `getScreenshot` возвращает один кадр, `streamScreenshot` — поток. Запрос выбирает дисплей `0` и встроенное изображение `PNG`, `RGBA8888` или `RGB888`; необязательные `width` и `height` ограничивают размер с сохранением пропорций, а без них кадр имеет размер 1920×720. Поток берёт новые кадры не чаще примерно 30 раз в секунду и пропускает кадры для медленного клиента. Пустой `Image` означает, что у приборки ещё нет текущего кадра. Для полноразмерного кадра RGBA нужен предел сообщения не меньше 6 000 000 байт.

Пусть `QNX_GRPC_PORT` взят из файла обнаружения, токен экспортирован в `QNX_GRPC_TOKEN`, а SDK лежит в `.local/toolchains/native-sdk`. Тогда grpcurl получает один кадр, а с `streamScreenshot` та же команда получает поток до прерывания клиента:

```sh
grpcurl -plaintext -max-msg-sz 6000000 -expand-headers \
  -import-path .local/toolchains/native-sdk/emulator/lib -proto emulator_controller.proto \
  -H 'authorization: Bearer ${QNX_GRPC_TOKEN}' -d '{"format":"RGBA8888"}' \
  "127.0.0.1:$QNX_GRPC_PORT" android.emulation.control.EmulatorController/getScreenshot
```
