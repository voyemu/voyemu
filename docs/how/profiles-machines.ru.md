# Профили и машины

Профиль описывает одну прошивку, машина — то, что из него делает подготовка. Подготовка читает профиль, запуск читает только машину. Причины — в записи [профили как источники, машины как результаты](../why/profiles-machines.ru.md).

## Профиль

Профиль — авторский каталог `profiles/<profile>/`. Имя кодирует линейку автомобиля, поколение Android, язык прошивки, её дату и версию, например `free-09-chinese-20260106-6.0.3`. `voyemu list` выводит известные идентификаторы профилей; у [опубликованных профилей](../profiles/index.ru.md) есть свои страницы.

| Файл или каталог | Содержимое |
| --- | --- |
| `profile.json` | Пин системного образа Android, настройки эмулятора, экраны, оригиналы с SHA-256, рецепты, устанавливаемые файлы, настройка гостя и проверки |
| `capture.json` | Какие штатные файлы импорт берёт из физического автомобиля |
| `profile-qnx.json` | Штатные образы QNX, аппаратный адаптер, настройки хранилища и оригиналы, взятые из другого профиля; есть только в профилях с приборкой |
| `components/` | [Компоненты](components.ru.md) профиля |
| `patches/` | Шаги рецептов, на которые ссылается `profile.json` |
| `files/` | Небольшие собственные файлы, которые подготовка устанавливает в гостя |
| `targets/<target>/` | Файлы для конкретной цели сборки, если они есть |

Поле `status` в `profile.json` равно `ready`, когда мультимедиа поддерживается, и `incomplete`, пока оригиналы профиля ещё собираются: тогда `fetch PROFILE --source=adb --serial SERIAL` читает их по `capture.json`. Поле `status` в `profile-qnx.json` равно `incomplete`, пока приборка экспериментальная. Поддержка каждого опубликованного профиля указана в разделе [профили](../profiles/index.ru.md).

Поле `title` в `profile.json` называет профиль в тексте для людей, например `Free 7.3.1`. Поле `platform` равно `qinggan09` или `qinggan11` для поколения Android 9 или Android 11 [платформы Free/Dreamer](../GLOSSARY.ru.md) либо `passion` для Passion. Поле `board` называет плату мультимедиа: `8155` для Qualcomm SA8155 или `nxp` для NXP i.MX 8QuadMax. Опубликованный профиль без этих полей или с другим значением Voyemu отклоняет.

Поле `features` в `profile.json` включает необязательные функции прошивки. Значение `true` у `original_navi` устанавливает штатное приложение навигации прошивки вместе с нужными ему рецептами; подготовка выбирает их по этому полю, а не по имени профиля. `system_upgrade` позволяет пересборке существующей машины заменить только систему Android и сохранить пользовательские данные вместе с пакетами, которые доставляет машина. `ui_observer_required` требует, чтобы каждая машина Android профиля несла наблюдатель UI. `measured_disk_reserve` заставляет подготовку резервировать место на диске, измеренное для закреплённого образа системы профиля, вместо большего резерва по умолчанию.

Поле `emulator` в `profile.json` задаёт эмулятор Android машины: `port`, `memory`, `gpuMode` и необязательно `cores`. `candidatePort` закрепляет порт эмулятора, который подготовка запускает для сборки машины; без него подготовка берёт свободный порт.

`gpuMode` выбирает рендерер эмулятора: `host` рисует на GPU хоста, `auto` и `auto-no-window` оставляют выбор эмулятору, `swiftshader_indirect` рисует программно на хосте, `guest` рисует программно внутри гостя. Машина запоминает рендерер, с которым её подготовили, и `start` запускает её с тем же; другие значения `build` и `start` отклоняют. Для `guest` хосту не нужен GPU, поэтому так можно подготовить и запустить машину на хосте без него, но экраны рисуются и анимируются гораздо медленнее, чем на GPU хоста.

## Цели сборки

Цель сборки готовит одну прошивку для одного ABI гостя. Оригиналы и рецепты остаются общими для профиля; поле `targets` в `profile.json` называет каждую цель и задаёт то, чем она отличается:

| Поле | Значение |
| --- | --- |
| `guestAbi` | ABI Android гостя, `arm64-v8a` или `x86_64` |
| `preparation` | `sdk` — подготовка образа SDK на работающем госте |
| `androidBase` | Закреплённая база Android из `profiles/common/android-bases/` вместо базы `android` профиля |
| `developmentKernel` | [Ядро разработки](components.ru.md#ядра-разработки) под ABI цели; цель другого ABI, чем у ядра профиля, задаёт собственное |
| `emulator` | Параметры эмулятора цели: `memory`, `gpuMode` и `acceleration` со значением `required` для гостя, которому нужно аппаратное ускорение |

`deps` и `build` берут цель с ABI гостя, как у процессора хоста; `--target` выбирает любую объявленную цель, и гость другого ABI работает в программной трансляции. [Профиль Passion](../profiles/passion-11-russian-20260403-2.1.4.80.ru.md) объявляет цели `arm` и `x86`. См. [выбор цели](preparation.ru.md#build).

Поле `wheel` в `profile.json` называет графику руля в `assets` и маршруты клавиш Android в `androidRoutes`; значение `com.voyemu.input.wheel` у `provider` передаёт руль в Android через этот поставщик контента профиля вместо маршрутов.

Общие части лежат вне профилей: `profiles/common/` содержит общие компоненты, значки и графику руля, а `profiles/common-qinggan-09/` и `profiles/common-qinggan-11/` — рецепты ядра разработки для каждого поколения Android, `profiles/common-passion/` — вариант рецепта `qinggan-11` для Passion.

Поле `fonts` в `profile.json` называет шрифты автомобиля, которыми рисует [окно](window.ru.md#шрифты): `primary` для всего текста и `fallback` для символов, которых нет в основном шрифте, каждый с весами `regular`, `medium` и `bold`. Шрифт — оригинал профиля или файл внутри штатного APK, каждый с размером и SHA-256.

Оригиналы в репозиторий не попадают. Пользователь импортирует их в `.local/profiles/<profile>/`, а профиль хранит только их имена, размеры и SHA-256.

## Машина

Машина — подготовленный каталог `machines/<name>/`. `voyemu build PROFILE` по умолчанию создаёт `machines/PROFILE`, в том числе для цели сборки с ABI хоста; цель другого ABI создаёт `machines/PROFILE-TARGET`. Команда `build PROFILE machines/NAME` задаёт другое имя. Каталог назначения должен быть новым и лежать прямо в `machines/` установки.

| Путь | Содержимое |
| --- | --- |
| `runtime.json` | Манифест машины с идентификатором профиля, ABI Android, образами гостей, загрузочными файлами и ресурсами с размерами и SHA-256 |
| `profile.json` | Встроенный профиль с учётом выбранной цели сборки |
| `android/` | Системный образ и образ раздела `vendor` Android, ядро, записываемые диски пользователя и кеша, установленные пакеты |
| `qnx/` | Загрузочные образы QNX и записываемый диск QNX; только если приборка подготовлена |
| `ui/` | Логотип Voyemu, штатные загрузочные анимации в `ui/startup/`, шрифты автомобиля в `ui/fonts/`, графика руля и маршруты кнопок |

`runtime.json` появляется последним, после проверочной загрузки гостей, поэтому каталог без него машиной не считается. Команды жизненного цикла выбирают машину по пути, относительному или абсолютному, в том числе вне корня установки, и узнают профиль из `runtime.json`.

## Копирование и перенос машины

В машине есть всё, что запуску нужно из профиля, поэтому она работает без `profiles/` и переносится одним каталогом. Записываемые диски внутри машины, в том числе слои QCOW2 Android, хранят установленные приложения, файлы и настройки, поэтому после чистой остановки копируется или архивируется весь каталог машины. Каждый слой QCOW2 ссылается на свой образ RAW по пути относительно слоя, поэтому копия работает и в другом каталоге. Состояние сеанса лежит отдельно, в `.local/machines/<name>/`, и создаётся заново, если его нет; см. [корни `.local`](local-roots.ru.md).

Для работы машине нужны установленные инструменты хоста и движок, совместимый с гостевым ABI из манифеста. Для запуска приборки нужна привязка QEMU и ANGLE в `.local/toolchains/installed.json`: её записывает подготовка машины на своём хосте. `deps` устанавливает движок, а `start` привязку не создаёт, поэтому на хосте без привязки машина запускается с `--cluster=off`. `voyemu check MACHINE_PATH` проверяет сохранённые файлы и настройку запуска, не запуская гостей.

Независимым копиям нужны разные имена каталогов: состояние сеанса привязано к имени каталога машины, а у машины не больше одного сеанса.
